MCPeek Documentation

Peek into MCP Protocol Compliance

MCPeek is a browser-based tool for testing and debugging MCP (Model Context Protocol) servers. It provides full protocol validation, tool testing, and comprehensive logging to help you ensure your MCP server implementations are compliant and working correctly.

Getting Started

MCPeek allows you to test any MCP server that supports HTTP/SSE transport. Here's a quick overview of the testing workflow:

1

Add Your MCP Server

Configure your MCP server by providing its URL and any required authentication headers.

2

Connect to the Server

MCPeek will perform the MCP handshake (initialize, notifications/initialized) and retrieve available tools.

3

Test Tools & Validate

Execute tools, view responses, and check protocol compliance through the validation panel.

Adding MCP Servers

To add a custom MCP server to MCPeek:

  1. Click on "+ Add Custom MCP Server" to expand the form.
  2. Fill in the server details:
    • Server Name: A friendly name for the server (e.g., "My Production Server")
    • Server URL: The full URL to the MCP endpoint (e.g., https://api.example.com/mcp)
    • Description: Optional description for your reference
  3. Click "+ Add Server" to save.
Note: Custom servers are saved in your browser's localStorage and will persist across sessions.

Managing Servers

Click on "List MCP Servers" to view, edit, or delete your configured servers. Each server entry shows:

  • Server name and URL
  • Number of custom headers configured
  • Edit and Delete buttons

Using Custom Headers

Many MCP servers require authentication or custom headers. MCPeek supports adding custom HTTP headers to all requests sent to a server.

Adding Headers

In the "Add Custom MCP Server" form, use the Custom Headers textarea to specify headers as a JSON object:

{
    "X-API-Key": "your-api-key-here",
    "Authorization": "Bearer your-token-here"
}

Common Header Examples

Use Case Header Configuration
API Key Authentication {"X-API-Key": "abc123"}
Bearer Token {"Authorization": "Bearer eyJ..."}
Basic Auth {"Authorization": "Basic dXNlcjpwYXNz"}
Multiple Headers {"X-API-Key": "key", "X-Tenant-ID": "tenant1"}
Security Note: Custom headers are stored in your browser's localStorage. Avoid using MCPeek on shared computers with sensitive API keys.

Connecting to Servers

After selecting a server from the dropdown, click "Connect" to initiate the MCP handshake.

Connection Process

MCPeek performs the following steps automatically:

  1. Initialize: Sends the initialize request with client capabilities
  2. Notification: Sends notifications/initialized to complete the handshake
  3. List Tools: Retrieves available tools via tools/list
  4. List Resources: If supported, retrieves resources via resources/list
  5. List Prompts: If supported, retrieves prompts via prompts/list

Connection Buttons

Button Function
Connect Initiates connection to the selected server
Refresh Token Refreshes OAuth token (for OAuth-enabled servers)
Disconnect Disconnects from the current server
Reset Clears all logs and resets the session

Server Information

Once connected, the Server Information section displays details about the MCP server:

  • Server Name: The name reported by the server
  • Version: Server version number
  • Protocol Version: The MCP protocol version supported
  • Capabilities: Features the server supports (tools, resources, prompts, etc.)

Capability Details

Click "Capability Details" to view the full JSON structure of the server's capabilities.

Protocol Validation

MCPeek validates all MCP protocol messages against the specification. The Protocol Validation section shows:

  • Initialize Response: Validates server info, protocol version, and capabilities
  • Tools List Response: Validates tool definitions and schemas
  • Resources List Response: Validates resource definitions
  • Tool Call Responses: Validates tool execution results

Validation Status

Valid: The response conforms to MCP protocol specification
Warnings: Minor issues that don't break functionality but should be addressed
Invalid: The response has protocol violations that may cause compatibility issues

Testing Tools

The Available Tools section lists all tools exposed by the connected MCP server.

Tool Cards

Each tool is displayed as a card showing:

  • Tool Name: The identifier used to call the tool
  • Description: What the tool does
  • Input Fields: Parameters the tool accepts (required fields marked with *)
  • Execute Button: Runs the tool with the provided inputs

Executing Tools

  1. Find the tool you want to test
  2. Fill in the required input parameters
  3. Click "Execute [tool-name]"
  4. View the response in the tool card

Tool Responses

After executing a tool, the response is displayed with:

  • Formatted Data: If the response contains structured data, it's displayed in a readable format
  • Content Retrieved: Collapsible section showing the raw content array from the response
  • Raw Response: The complete JSON-RPC response for debugging

Resources & Prompts

If the MCP server supports resources or prompts, additional sections will appear:

Resources

MCP resources are data sources the server can provide. The Resources section shows:

  • Resource URI
  • Resource name and description
  • MIME type
  • Read button to fetch the resource content

Prompts

MCP prompts are predefined prompt templates. The Prompts section shows:

  • Prompt name
  • Description
  • Required arguments
  • Execute button to run the prompt

Activity Log

The Activity Log at the bottom of the page shows a detailed timeline of all operations:

  • Connection events: Initialize, handshake completion
  • Request/Response logging: All MCP method calls
  • Header logging: When custom headers are used, the URL and headers are logged
  • Errors: Any errors that occur during testing
  • Validation results: Protocol compliance checks
Tip: The activity log is invaluable for debugging connection issues. Check it first when something doesn't work as expected.

Troubleshooting

Connection Failed

CORS Errors

If you see CORS errors in the browser console, the MCP server needs to allow cross-origin requests. The server must include these headers:

Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: Content-Type, Authorization, X-API-Key

Authentication Errors

401 Unauthorized

Check that your custom headers include the correct authentication credentials. Verify the header name and value format match what the server expects.

Tools Not Loading

Empty Tools List

If no tools appear after connecting:

  • Check the Activity Log for errors
  • Verify the server implements tools/list
  • Check Protocol Validation for response issues

SSE Servers

Server-Sent Events

MCPeek supports SSE transport for servers that use it. SSE servers are typically identified by URLs containing /sse. Note that browser-based SSE has CORS limitations.

About MCP Protocol

The Model Context Protocol (MCP) is a standardized protocol for communication between AI applications and tool providers. Key concepts:

Concept Description
Tools Functions that can be called by AI models to perform actions
Resources Data sources that can be read by AI models
Prompts Predefined prompt templates with variable substitution
Capabilities Features a client or server supports

Protocol Version

MCPeek uses protocol version 2024-11-05 for the handshake.

JSON-RPC

MCP uses JSON-RPC 2.0 for message formatting. Each request has:

  • jsonrpc: Always "2.0"
  • id: Request identifier
  • method: The MCP method to call
  • params: Method parameters
